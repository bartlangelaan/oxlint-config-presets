This is a [Next.js](https://nextjs.org) project bootstrapped with
[`create-next-app`](https://nextjs.org/docs/app/api-reference/cli/create-next-app),
styled with Tailwind CSS and [shadcn/ui](https://ui.shadcn.com) (Base UI primitives).

It's a documentation-style site for [oxlint-config-presets](..): browse every
ESLint rule oxlint targets, see which generated config presets enable or
disable a given rule, and track oxlint's ESLint-rule migration progress over
time.

## Data pipeline

The site reads static JSON committed under `src/data/`, regenerated by three
scripts (run in this order — each depends on the previous one's output):

- `pnpm collect-data` — cross-references `oxlint --rules --format json` and
  `@oxlint/migrate` against the ESLint plugins oxlint targets (the same set
  oxc's own `tasks/lint_rules/src/eslint-rules.mjs` uses), and joins in which
  `packages/oxlint-config-presets/configs/**/*.json` presets enable each rule.
  Writes `rules.json`, `plugins.json`, `configs.json`.
- `pnpm collect-history` — samples every oxlint release ever published on npm
  and counts implemented rules (and autofix status, where reported) at each,
  to build a real (not synthetic) time series of oxlint's own progress.
  Writes `oxlint-migration-history.json`: each sample carries the global
  totals plus a `byScope` breakdown (totalImplemented/fullyMigrated) per
  plugin, so this one file covers both the overall chart and every
  per-plugin chart. Results are cached under `.cache/` (gitignored) so
  re-runs only fetch new releases.
- `pnpm collect-eslint-history` — separately, for every ESLint plugin oxlint
  targets, walks that plugin's _own_ npm release history (not oxlint's — a
  plugin like eslint-plugin-unicorn releases on its own schedule) and counts
  eligible rules at each of its own releases, by reading rule files straight
  out of each published tarball without executing any of that code. Writes
  one `oxlint-migration-history-<scope>.json` per plugin (its own
  release-dated "target" series — merging every source package's release
  events for plugins backed by more than one, e.g. "react"), and merges all
  of them into a global target-over-time series written into
  `oxlint-migration-history.json`'s `targetHistory` field. The
  migration-progress charts plot this target series and oxlint's own
  implemented/fully-migrated series together on one real (not evenly-spaced)
  date axis, even though the two have entirely different sample dates.
  Results are cached under `.cache/` (gitignored) too.

Re-run all three after bumping the `oxlint` devDependency or regenerating
configs in `packages/oxlint-config-presets` — or just run `pnpm before-commit`
from the repo root, which does this (and runs tests/fmt/lint) automatically.

## Getting Started

From the repo root (or this directory) with the workspace installed:

```bash
pnpm --filter website dev
```

Open [http://localhost:3000](http://localhost:3000).
